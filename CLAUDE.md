# Ensō

Android browser for the Galaxy Z Fold 8, built on GeckoView and Mozilla Android Components. It syncs Zen Browser's Spaces.

- **Spec:** [docs/SPEC.md](docs/SPEC.md). It is the source of truth for behavior, layout and the build order.
- **Mockups:** [docs/mockups/](docs/mockups/). Filenames start with the spec's board numbers (for example `4 · Tab sheet.png` is board 4). Look at the relevant boards before building any UI.
- **Logo:** [docs/logo.png](docs/logo.png), an ensō brush circle. **Brand files** are in [docs/brand/](docs/brand/): `enso-icon.svg` (the app icon) and `enso-mark.svg` (the mark alone). The fidget's boards are `docs/mockups/F1–F4`.

## How we work

- Build **one step of the spec's build order at a time**. Each step must build, install and run on the Fold before the next one starts.
- Don't build UI or features from later steps early, even as stubs.
- If the spec is unclear or silent, ask instead of guessing. The spec lists its own open questions at the end.
- Step 8, **split view and Glance**, is done, in three passes:
  - **8a (done): split view on the inner screen.**
  - **The cover's bottom bar (done)** (boards B1–B4), in the style of Arc Search, came in before 8b. It replaced the top bar.
  - **8b (done): splits sync both ways with Zen.**
  - **8c (done): Glance** (board 8), on both screens.
- Step 9, **Extensions**, is done: bundled uBlock Origin, the Extensions list, popups and settings pages in a sheet (9a), and installs from addons.mozilla.org with an Ensō-style prompt and daily updates (9b). The user dropped the recommended extensions list for a "Find more add-ons here" link.
- Step 10, **Polish**, is done, in four passes:
  - **10a (done): real favicons** with letter fallbacks: the loaded page's icon, Zen's synced icon for tabs that aren't loaded, AC's icon cache or the site's `/favicon.ico`, then the letter. The user had the neutral circles behind them removed; only mostly white icons get a dark circle.
  - **10b (done): the tab sheet's blurred snapshot, and animations** (rows sliding as tabs open, close or move; folders opening smoothly; the start screen cross-fading with pages; cards fading in; favicons fading in).
  - **10c (done): dark mode.** It follows the system, with a `themeMode` setting (System, Light, Dark) to override it, and pages are asked for their dark version too.
  - **10d (done): settings screens**, built to the sketch the user approved (`settings/`).
    - **The look** was redone after Arc Search's settings, to be cleaner and more minimal (`SettingsRows.kt`).
      - **Type:** small (`SettingsType`): 15 sp rows, 12.5 sp second lines and group names, 17 sp headings.
      - **One left margin** (`SettingsMargin`, 16 dp): group names, icons, the back arrow, and the titles of rows without an icon all sit on it. Rows don't keep an empty icon column, so a screen's rows either all have icons (Site Settings) or none do (All settings).
      - **Choices** show their value as a line under the title, and a tap opens a menu below the row with the current option checked (`ChoiceRow`, `MenuRow`). There are no segmented controls, sliders or chevrons. Numbers use a small stepper (`StepperRow`): page zoom and the space menu's hold time.
      - **Switches** are drawn at 80% (`scaledLayout`), and the whole row toggles them.
    - Settings (the actions sheet on the cover, the ⋮ menu unfolded) opens `SiteSettingsContent` for the page on screen: security, Desktop site (`SiteChoices`, by host, in `enso_sites`; flipping it to what the screen gives forgets the choice), tracking protection (AC's `TrackingProtectionUseCases` exceptions), and clearing the site's data (Gecko clears its base domain), after a confirmation dialog. With no http(s) page it opens All settings.
    - `AllSettingsContent` writes `Settings` and calls `MainActivity.settingChanged`, which applies what it can at once (theme, layout, desktop sites, tracking protection level, extension updates) and bumps `settingsRevision`, which the overlay reads settings through.
    - Cover: `BarPanel.SiteSettings` and `BarPanel.AllSettings` (`BarSettings`). Unfolded: `SettingsCard` over the page card. Sync with Zen moved from the ⋮ menu to the top of All settings.
    - Gecko's Enhanced Tracking Protection is on (`trackingProtection`, Standard by default). Standard blocks trackers' cookies; their scripts only under Strict.
- Step 11, **site permissions** (`permissions/`), is done, built to the sketch the user approved: Ensō's card for a site's request, Android's own permission when it's missing, each site's answers remembered and shown in Site Settings, and site notifications while the site is open. Not yet checked on the Fold: the Allow path through Android's dialogs (the user's to grant), and a site notification showing.
- Step 12, **downloads** (`downloads/`), is done, function first. Tested on the Fold: the prompt, saving to Downloads, the notification permission asked once, and the completion notification.
- The **polish pass** after the build order is done: the downloads UI, Reader view, Find unfolded, a check of the unfolded screen (the sync sheet now sits on the page card), and the untested features, which the user walked through on the phone. The ensō fidget is on the cover only.
- Next: **a final pass by Claude Fable**, starting with a read-only review of Zen sync, in its own session.
  - The review is `docs/reviews/zen-sync-review.md`. None is open. The last six haven't run on the Fold yet: the phone still has the build from the morning of Nov 13. Before their first real sync, back up, check in dry run, and ask the user.
  - Tested on the Fold on Nov 12, in dry run and then for real, with test tabs and a test folder that were removed afterwards: the first sync after the update (it drops the mirror, downloads everything and sends nothing), a kept tab going up and coming back as synced, a folder deleted in its two steps, and 11 deletions at once refused and put back, with the sheet's line. - The start screen (board 9) has the ensō fidget (boards F1–F4), which the user asked for as a side piece alongside step 10. So does the app icon.
- When a behavior could reasonably differ per person, the user wants it built behind a value in `Settings.kt` so it can become a setting later.

## Project

- Kotlin, Gradle (Kotlin DSL) with the wrapper, and a version catalog in `gradle/libs.versions.toml`. Application ID and package are `app.enso.browser`.
- Mozilla libraries come from `https://maven.mozilla.org/maven2/`. GeckoView comes in through `browser-engine-gecko`, so bumping `mozilla-components` bumps both together.
- Android Components keeps many modules as internal dependencies. If the compiler says it "cannot access" an AC class, declare that module (for example `concept-engine`) in the catalog yourself.
- AC 158 requires `compileSdk` 37.2, which is why `app/build.gradle.kts` uses the minor-version `compileSdk { }` block.
- **Sign-in client ID:** `sync/MozillaAccount.kt` signs in with **Firefox for Android's OAuth client ID** (`a2270f727f45f648`), as Fenix forks like Dejavu do, because Mozilla only gives Sync access to its own apps. That's agreed for personal use and testing only. **Before publishing, get Ensō its own client ID from Mozilla and replace it.**
- **Reused code:** `sync/SyncClient.kt`, `sync/SyncCrypto.kt` and the emoji table in `ui/ZenIcons.kt` are adapted from Dejavu ([by-architect/Dejavu](https://github.com/by-architect/Dejavu), MPL 2.0). They keep their MPL headers and must stay MPL. Zen's record format comes from Zen's `src/zen/sync/ZenSpacesSync*.sys.mjs` (also MPL 2.0).
- **App-services setup:** `EnsoApplication` (main process only) runs `AppServicesInitializer.init` and `RustHttpConfig.setClient` before any Places or account code runs.
- **AC's logs:** debug builds add AC's `AndroidLogSink`, so Android Components' own logs (tags like `BrowserIcons`) reach logcat. Without it, AC fails silently. They include page URLs, so don't quote them to the user.
- `app/build.gradle.kts` has a capability rule that picks GeckoView's copy of `glean-native`. GeckoView's omni build bundles it, and application-services (Places) asks for the standalone one. Keep the rule while both are in the build.
- The build is limited to `arm64-v8a`, the Fold's chip type.

## Code map

- `Components.kt`: app-wide singletons, created lazily by `EnsoApplication`: `GeckoEngine`, `BrowserStore`, the use cases, `SpacesStore`, `TabManager` and `PlacesHistoryStorage`. Only one `GeckoRuntime` may exist per process, and it lives here.
  - **Page zoom:** the runtime gets a `displayDensityOverride` of the screen density × `pageZoomPercent`, a true zoom of text, images and layout.
    - Gecko reads it only at startup and for the whole engine, so it can't change live or differ per screen. Both screens are 420 dpi anyway.
    - The only live option is text size (`fontSizeFactor`). A per-screen zoom would need a built-in extension (step 9).
  - History goes into Firefox's Places database through `HistoryDelegate`; the palette reads it, and step 5 syncs it.
  - **Add-on web API:** the runtime turns on `extensionsWebAPIEnabled`, as Firefox for Android does, so the add-on site installs through `mozAddonManager`. Without it the site falls back to opening the `.xpi`, and nothing installs.
- `DesktopSites.kt`: desktop sites while the sidebar layout shows.
  - addons.mozilla.org always gets its mobile version (`alwaysMobile`, by the tab's page when its session starts or the screen changes). The site serves both versions at `/en-US/firefox/` and picks one by user agent; the desktop one lists Firefox's desktop add-ons.
  - AC's Gecko engine has no desktop default for new sessions, so a store middleware switches each session as it's linked (`LinkEngineSessionAction`), before the engine middleware loads its first page. That's why it comes first in the store's middleware list.
    - It also sets the tab's `desktopMode` in the store itself (`UpdateTabDesktopMode`). AC reports a switch only through the observer it registers while linking, after this, so the store never heard, and site settings showed Desktop site off on pages that had it.
  - Folding or unfolding switches open sessions with `toggleDesktopMode(reload = false)`: by the user's choice, pages keep their version until they next load.
  - Tabs in a split keep mobile sites (`setActive`'s `mobileTabs`) unless `desktopSitesInSplit` is on.
- `spaces/`: the local spaces model, shaped after Zen so step 5 can sync it.
  - Structure: `SpacesState` holds the spaces and the shared Essentials. A `Space` holds its pinned items (tabs and folders, in order), its open tabs and its splits.
  - Edits are pure functions in `SpacesEdits.kt`.
  - `SpacesStore` saves the model to `files/spaces.json` 500 ms after a change, and right away in `onStop`.
  - Every `SpacesStore.update` runs `withValidSplits`, which drops splits left with fewer than two of their space's tabs. Edits that close or move tabs therefore don't tidy splits themselves.
- `TabManager`: the only place tabs are opened, selected, closed or unloaded. Don't add or remove tabs in the `BrowserStore` directly.
  - The model and the `BrowserStore` share tab IDs. A tab exists in the BrowserStore only while it's loaded, so pinned tabs and Essentials can sit unloaded.
  - It copies URL and title changes, page-opened tabs (`WindowFeature`) and selection back into the model.
  - Any open tab that leaves the BrowserStore is removed from the model. A bug that drops BrowserStore tabs therefore deletes them from the user's saved tabs.
  - No selected tab is a real state: the start screen shows.
  - `load` gives tabs a page without selecting them: the other pages of a split.
- Quick Tabs: `Tab.quick` holds `lastViewedAt`, and sync must skip these tabs.
  - New searches from bottom search, the inner palette and the tab sheet's search field create them, and so do pages a Quick Tab opens. Editing the URL from the actions sheet loads in the current tab.
  - On the cover they live in the bottom bar's stack; the tab sheet leaves them out unless `quickTabsInTabSheet` is on.
  - Expiry runs in `onStart` and every minute while the app is open. Pages on screen (both of a split's) are never cleared while you're viewing them.
- `tabsheet/`:
  - `TabSheet.kt` is the cover tab sheet (board 4). Quick Tabs get a gold outline.
    - **Frosted backdrop:** as the sheet opens, `MainActivity.captureFrostedPage` captures the page, and `frostedCopy` blurs a copy an eighth of its size once. `FrostedOver` provides it as `LocalSurfaceBackdrop`.
      - `SurfaceBackdrop.frosted` blends the page and the space colors (at 80%, `FROSTED_COLORS`) into one small picture of the whole window, and every `spaceSurface` inside draws it lined up with the window, so rows sliding over it are the same pixels.
      - Draw it in one layer. Rows clip to rounded corners, and layering the page and the colors separately left each layer's softened edge showing as an outline around every row.
      - The plain colors cover it at first and fade out once the capture arrives. Over the start screen there's no capture, so the sheet stays its plain colors.
    - **Rows animate** (`Modifier.animateItem`): they fade in and out and slide into place as tabs open, close or move, and as folders open and close. The sidebar's rows do the same through `animatedItem`.
  - `SwipeToClose` closes a row as soon as the finger lifts on a swipe that will dismiss (a frame later, so a fling back can win), not in `SwipeToDismissBox`'s `onDismiss`, which waited for the slide-away spring's long tail and held the rows below for a second or two.
  - Rows that can swap which tab they show (like the current-tab card) must key their swipe state by tab ID, or a dismissed state carries over and closes the next tab.
  - `TabMenu.kt` is the hold menu (board 4b).
    - On a Quick Tab it shows the spec's menu: Add to [space], Add to another space (the wave as a picker; hidden with one space) and Close tab.
    - On other tabs and folders it shows pin, unpin, folder and Essentials actions. While signed in, these sync to Zen.
    - On a tab in a split it also shows Unsplit tabs.
  - `SplitRow` shows a split's tabs as one row, each in its own part, and each part swipes on its own. On the cover sheet, the current-tab card shows the whole split.
    - Folder names confirm with the keyboard's Done key too, since a floating overlay can cover the dialog's button.
- `sync/`: Zen sync over the user's Mozilla account.
  - **Format:** Zen's `spaces` collection (version 3). Records decrypt to `{id, kind, data}`; the kinds are space, folder, tab, split, container and layout.
  - **What Zen sends:** by default only pinned tabs and Essentials. Normal tabs also need `zen.spaces-sync.normal-tabs` turned on in Zen's about:config.
    - With it off, Zen skips every record that says `pinned: false` and uploads each space without those tabs in `children`. The phone's kept tabs still sync between phones: Ensō shows an open tab by its own record, listed or not (see the mapper).
  - **Account:** `MozillaAccount` asks for only the Sync scope, with no `SyncConfig`, so Firefox's history, bookmark and password engines never sync.
  - **Engine:** `ZenSpacesEngine` checks `meta/global` and `crypto/keys`, then syncs three ways against `ZenMirror` (`files/zen-spaces-mirror.json`), the server state the phone's model last took in, kept as whole records.
    - It works out the phone's changes against the mirror first, then downloads what changed on the server.
    - **The mirror must never know more of Zen than the model does.** The phone's changes are the difference between the two, so a mirror that was ahead made the next sync upload that difference: it deleted what Zen had added and re-created what Zen had deleted.
      - The engine doesn't save the mirror. It returns two (`ZenSyncResult.Synced`), and `ZenSyncRound` saves one (`engine.save`).
      - `mirror`, once Zen's state is applied to the model: the model first, then `spaces.json` (`flush`), then the mirror.
      - `unapplied`, when the apply is skipped (an edit during the sync, or a dry run with unsent changes): the old mirror plus only the records this sync uploaded, at the old server time. The next sync downloads Zen's changes again.
      - A downloaded record only counts as Zen's change (`incoming`) when it differs from the mirror's copy, so the phone's own uploads coming back in that download aren't held against its next edit.
      - **The stamp:** the model says which mirror it reflects (`SpacesState.zenApplied`, a `ZenStamp` of the mirror's `lastModified`, `syncId` and `ownUploadAt`, set as Zen's state is applied). When the saved mirror isn't that one (a restored `spaces.json`, a kill between the two saves, an install from before the stamp), the engine drops the mirror: that sync downloads everything and uploads nothing, and Zen's state wins.
        - `ownUploadAt` is the server time of the phone's upload in an `unapplied` mirror, which keeps the old `lastModified`. Without it, a backup from just before that upload still matched, and the phone sent its older state of those records again. The model's stamp is updated with it, though the rest of the model stays as it is.
        - After a restore, the tabs that were the phone's own in the backup (kept, not yet synced) stay and go to Zen as new tabs in the next sync, as on a new phone.
    - Where both sides changed the same record, Zen wins. The rest uploads with `X-If-Unmodified-Since`, in batches when it doesn't fit one request. A conflict makes `ZenSync` sync again.
    - **Snapshots** (`ZenSnapshotStore`): before its first write it saves the whole encrypted collection to `files/zen-spaces-snapshot.json`. A snapshot says whose it is (storage user, sync id, the time of the account's keys).
      - When those change (another account, a password reset, a collection started over), the next write takes a new one, and the old one is kept aside. The user's snapshot from before this, which doesn't say whose it is, is taken on as this account's if the account's keys read it.
      - **Kept aside** in `files/zen-snapshots/<name>.json`, the latest 5: `replaced-<time>` (a snapshot that was replaced), `before-restore-<server time>` (the collection just before a restore), `before-deletions-<server time>` (the mirror from before a sync that brought or sent 5 or more deletions, `SNAPSHOT_AT_DELETIONS`) and `before-reset-<server time>` (the mirror from before the collection's sync id or keys changed). The last two are made from the mirror, encrypted again, so they restore like the others.
      - **A restore** uploads the snapshot's records as they are and deletes every other record. It refuses a snapshot that is empty, of another storage user, or whose records the account's keys can't read: after a password reset those would arrive unreadable while everything readable was deleted.
    - A sync whose changes hold more than 10 deletions uploads nothing at all (`refusedDeletions`), since that looks like lost data. Zen's state then goes over the model as usual, which puts back what was removed, and the sync sheet says so for a day (`ZenMirror.refused`). The next sync sends whatever else was waiting.
    - **Records that can't be read** (`ZenMirror.unread`): a record that fails to decrypt or parse is remembered by id. Each sync asks for those again by id (`downloadAgain`), and until one reads, none of the phone's changes to it goes up, since the mirror only has an older copy of it, or none.
      - While anything is unread, no folder's deletion goes up either, because an unread record could be in any folder. Nor does it while a record this sync downloaded says it's in the folder. `SyncFuzzTest` found that one: after the mirror started over, the phone had no copy of an unreadable tab, saw an empty folder, and deleted it.
    - **Deleted ids** (`ZenMirror.gone`): every id the phone has seen a deletion for, its own included. The projector needs it to tell a listed id that was deleted from one the server never sent a record for (see "Ids without a record").
    - **The device record** goes up last, and nothing that happens to it fails the sync (`withDeviceRecord` catches everything). The phone's changes are on the server by then, and a sync that failed there left the mirror without them: the next one took the phone's own uploads for Zen's and put them over a newer edit.
  - **Projector:** `ZenSpacesProjector.zenChanges` turns the phone's model into records.
    - Each record starts from the server's copy, and only fields the phone owns change: pinned, Essential, space, folder, children, folder names, and new tabs' pages. An untouched record comes out identical and isn't sent.
    - Containers, icons, themes and live folders' children pass through.
    - **Splits:** the space's splits go to Zen in Zen's format (`splitId`, `gridType`, `pinned`, `tabs`, `workspaceUuid`, `folderId`), with the split's id in its parent's `children` in place of its tabs.
      - A split only goes when all its tabs go under the same parent. A Quick Tab doesn't go, and Zen can't hold a pinned tab with an open one (it would duplicate the pinned tab), so those splits stay on the phone.
      - Zen's own splits the phone hasn't taken on pass through while their tabs still sit together, unless the phone ended them (`endedSplits`) or put one of their tabs in a split of its own. That kept the first sync after the update from deleting the user's existing Zen split.
      - Zen keeps the id the phone gives a new split (its `groupFetchId`).
    - It only deletes items the phone showed, so a record the phone never displayed isn't removed for being missing.
    - **Ids without a record** (`keepingUnknown`): Zen lists a tab that has no page yet in its parent's `children` without sending a record for it, and a record can fail to read. The phone can't show those, and it leaves them where they are in every list it writes: a space's or folder's `children`, a group of `layout.essentials`, a split's `tabs`. Each stays after the id it followed. Writing them out made Zen put them back, and the two traded the record on every sync.
      - An id whose record was deleted (`gone`) isn't kept: it's only left over in the list. That happens when the phone's deletion goes up while Zen's change holds the parent back.
      - One of Zen's splits with such a tab keeps its place in `children` while the phone has the split's other tabs together.
      - A deleted folder still goes up with empty `children`, whatever Zen listed in it. Zen then sends its own list again, and the folder comes back on the phone.
    - **Folders are deleted in two steps**, and only ones the user deleted (`SpacesState.deletedFolders`, as `endedSplits` for splits). Zen deletes the tabs still inside a folder when the folder's deletion arrives (`folder.delete()` in its applier).
      - While the server's copy has children, or any record still names the folder as its `folderId` or `parentFolderId` (a move Zen's change held back, say), the folder only goes up with empty `children`.
      - Its deletion follows in a later sync, once the mirror shows that everything has left it. That sync comes 3 seconds later, as for anything still unsent (see `ZenSync`).
      - The mapper hides a deleted folder while Zen's copy is empty. If Zen's copy has something in it again, the folder comes back and the deletion is dropped.
    - A tab on a blank page (`about:blank`) isn't sent while Zen has no record of it. One Zen already has keeps Zen's page; leaving it out would delete it from Zen.
    - An open tab the server has a record of, but which the server's copy of its space doesn't list, stays out of `children` (`leftOut`). Zen left it out, and putting it back would have the two trade the space's record on every sync. Its record still goes up, a close still deletes it, and pinning it lists it again.
    - A tab from Zen keeps Zen's URL unless `syncTabNavigations` is on.
    - New IDs follow Zen's formats: tabs `<time>-<uuid>` and folders `<time>-<0..99>`. Spaces are `{uuid}`, and the phone can't create them.
  - **Mapper:** `ZenSpacesMapper` applies the mirror through `TabManager.applySpaces`. Zen owns spaces, pinned tabs, folders (which can nest), split views and Essentials. The phone keeps its Quick Tabs and its own open tabs (`Tab.synced` tells them apart).
    - Zen's splits become phone splits (`Split.synced`), keeping the sizes the phone gave them while their pages and layout stay the same. Zen's splits come first, so where a tab ends up in two, Zen's wins.
    - The phone's own splits stay unless they were Zen's and Zen no longer has them, which means they ended on the desktop. Splits the phone ended stay out until Zen has dropped them too (`endedSplits`).
      - One exception: a split that was Zen's and that the phone has made into one Zen can't hold (`zenCanHold`: a Quick Tab in it, or its tabs no longer under one parent) left Zen by the phone's own upload. It stays, as the phone's own (`synced` cleared), and goes back up if Zen can hold it again.
    - Open tabs follow Zen's order, and each phone-only tab stays after the tab it followed.
    - **Open tabs belong to the space their own record names**, as in Zen's applier, where `children` only orders them. An unpinned tab record that no `children` list still shows in its space (`leftOut`): after the tab it followed on this phone, or last on a phone that never had it. Only its deletion takes it away.
    - **The phone's own pinned side survives** Zen's state being applied, as its own open tabs do: tabs it pinned (`synced` false), folders it made (`Folder.synced` false) and Essentials it added that Zen hasn't got yet. That's all of them before the first sync, and the latest ones when the mirror starts over or part of an edit had to wait.
      - They go after Zen's pinned items of the same space, or of the first Zen space when theirs isn't Zen's. A tab in one of Zen's folders stays in it. If that folder was Zen's and is gone there, the tab moves out of it, and the folder isn't brought back.
      - A folder of the phone's own with nothing of its own left in it is dropped.
    - A tab ID must never be listed twice, or Zen gets duplicate children. The Essentials are read first, so a space that still lists one doesn't show it again, and the phone's own copy of a tab is dropped when Zen has that id anywhere (`zenTabs`): pinned, in another space or as an Essential, not only among that space's open tabs.
  - **Space look:** the accent comes from the theme's primary gradient color, and `Space.gradient` keeps all of its colors (Zen allows up to three). Icons go through `ZenIcons`.
  - **Essentials are per container**, as in Zen.
    - `layout.essentials` maps a container guid ("default" for none) to tab ids.
    - Each space has a `container` and shows `essentialsFor(space)`.
    - A setting (`essentialsPerContainer`) turns this off to show every Essential everywhere, matching Zen's own option.
  - **`ZenSync`:** runs the account and status. `ZenSyncSheet` (from All settings › Sync with Zen) shows the status. Unfolded it's centered on the page card (`PromptArea`), not the window.
    - It syncs on start, every 5 minutes, and 3 seconds after a tab sheet edit (`localEdited`). Opening or closing a folder isn't one (`TabSheetActions.toggleFolder`): it stays on the phone, and it used to stop a running sync from applying Zen's state.
    - `ZenSyncRound` is one sync from start to finish, kept free of Android classes so the unit tests can run it (`SyncedModel` stands for `SpacesStore` and `TabManager`).
    - **Quick checks:** in between, while the app is open, it asks every `zenSyncCheckSeconds` (30) whether Zen changed anything (`checkForChanges`). That's one `info/collections` request (`engine.serverChanged`) against the collection time the last sync left, which the engine keeps in memory, and a full sync only follows when it differs. Zen uploads within seconds of a change, so its changes show on the phone within about half a minute.
      - With no collection time on the phone, the check would say "changed" every time, which made it a full sync every half minute. So it compares both sides (a collection with nothing in it hasn't changed), and it doesn't run while a sync can't get anywhere by itself (`allowsQuickCheck`): signed out of sync, Ensō needs an update, Zen's spaces sync is off, or the last sync failed. The 5-minute sync still tries.
    - **Held-back changes:** where Zen changed a record the phone also changed, the phone's version waits (`held`). Once Zen's state is applied, it syncs again 3 seconds later, worked out on top of Zen's versions, instead of at the next 5-minute sync.
    - **Follow-up syncs:** more generally, after Zen's state is applied, `ZenSyncRound` works out whether the model still differs from the mirror (`zenChanges`), and asks for another sync 3 seconds later if it does: for held-back changes, what's left after a refused sync, a folder's deletion after it went up emptied, and what's the phone's own from before a sync that only downloaded. Not after a sync that couldn't send what it had, and at most 5 times in a row (`MAX_FOLLOW_UPS`); the 5-minute sync picks up the rest.
    - **Sync device:** each sync makes sure the account's Sync device list (the `clients` collection) has this phone (`SyncDevice`: type mobile, the account device's id and name, an id made once in `syncDeviceRecordId`). It goes up again when it changes or after 6 days, since Firefox ignores device records older than 7, and the mirror notes what it last sent (`deviceRecord`, `deviceUploadedAt`).
      - Why: Zen (Firefox's sync scheduler) only syncs every 10 minutes, and as soon as you come back to the computer or wake it, while it counts another device. With one device it waits an hour. A push from another device only makes it sync its device list, never the spaces, so Ensō can't make Zen sync on demand.
      - Signed out, the phone's account device goes, and Firefox hides device records whose account device is gone.
    - It never applies Zen's state over an edit made during a sync; it saves the `unapplied` mirror and syncs again instead.
    - In dry-run it doesn't apply Zen's state while the phone has unsent changes, so the test edits survive. The mirror stays where it was then too.
  - **Sign-in:** the page opens in a Quick Tab, and `FxaWebChannelFeature` completes it.
  - **Unit tests** (`app/src/test/…/sync/`, `./gradlew testDebugUnitTest`): they run the real engine, projector, mapper and `ZenSyncRound` on the JVM.
    - `FakeSyncServer` is the account's storage in memory, with real encryption; `zenUploads` changes it as Zen's desktop would, and its hooks make things happen mid-sync (an edit, Zen's own upload, a lost answer).
    - `Phone` (`SyncHarness.kt`) is the phone's side over an in-memory model, mirror and `spaces.json`; `syncUntilSettled` syncs again while a sync asks to, as `ZenSync` does.
    - Each fix from the review has tests that failed before it. Add one for any change to how the mirror, deletions or folders sync.
    - `SyncFuzzTest` plays random edits on both sides with syncs interrupted every way the app can be (an edit mid-sync, a dry run, Zen uploading first, a lost answer, a kill, a restored `spaces.json`). Half its scenarios run against a Zen with normal-tab sync off. Its Zen also lists tabs it sends no record for, and uploads records the phone can't read. It has no split views.
      - After each of the phone's uploads it checks that the phone only deleted what its user removed, brought nothing back, listed nothing twice, wrote no id it can't show out of the space, and wrote over no record it couldn't read.
      - After each time Zen's state is applied, it checks that the phone lost no tab of its own and no open tab the server still has.
      - At the end the two sync until neither has anything to say (they mustn't keep trading changes), and the phone must show what a new phone would.
      - It runs 300 scenarios. After any change to sync, run 30,000 (about seven minutes): `ENSO_FUZZ_RUNS=30000 ./gradlew testDebugUnitTest --rerun --tests '*SyncFuzzTest*'`. It found the stamp's `ownUploadAt` gap, a way the phone and a Zen without normal tabs kept trading a space's record, and a folder deleted with an unreadable tab in it.
    - One case it knows and allows: the phone sends again a tab or folder of its own that Zen deleted before the phone knew the upload had arrived (a lost answer), or before it had taken a sync in (an edit during every sync since it made the item).   - **The Downloads page** (polish pass): `DownloadsList` (shared by the cover's `BarPanel.Downloads` and the unfolded card from the ⋮ menu) over `MainActivity.downloadItems`, kept from the store's `downloads`. `downloadListActions` opens a finished file through AC's `FileProvider` (`<package>.feature.downloads.fileprovider`, which covers external storage), falling back to Android's Downloads list; a retry re-adds the download under a new id, which the middleware starts again; removing keeps the file.
  - **The chevron:** a download id that newly appears running sets `downloadJustStarted` for 2 s (the first look at the store only takes in what's there, so restored downloads don't flash): the chevron is a download button that opens the page. After that `DownloadRing` draws round it while one runs. Gecko keeps fetching while the prompt shows, so a download tapped late can finish at once, with no ring.
  - The actions sheet's small Downloads button and the ⋮ menu's entry show only while `recentDownloads`: one running, or one within `Settings.recentDownloadsHours`.
- `extensions/`: WebExtensions (step 9), on AC's `WebExtensionSupport`, which keeps installed extensions in the store (`state.extensions`) with their toolbar actions, popup sessions and options pages.
  - `Extensions` (in `Components`, started by `EnsoApplication`): installs the bundled uBlock Origin once (`bundledExtensionsInstalled`) and answers its own permission prompt (`webExtensionPromptRequest`), and routes the tabs extensions open, close or select through `TabManager`. Extension tabs are Quick Tabs (`openExtensionTab`).
    - The signed package is in `assets/extensions/`. AC refuses `resource:` URLs to install from (GeckoView would take them), so it's copied to the cache dir and installed from a `file:` URL.
    - uBlock Origin is GPL-3.0: its license and a notice with its source are in `assets/licenses/`.
  - `ExtensionsList` shows `extensionRows(state)`: built-in extensions left out, and the toolbar button merged with the tab on screen's override (uBlock Origin's count is per tab). Its icon is the toolbar button's, or the extension's own when it has none (or is switched off).
    - It ends with "Find more add-ons here" (`ExtensionListActions.findMore`), which opens `Extensions.ADDONS_SITE_URL` in a Quick Tab and closes the panel or card.
  - **Prompts:** `Extensions.prompts` queues Gecko's questions and notices as `ExtensionPrompt`s; the overlay shows the first in `ExtensionPromptCard`, over everything, and `answer` passes the reply back once. A tap while the card fades out finds it gone from the queue, so Gecko's prompt isn't completed twice.
    - From the store's `webExtensionPromptRequest` (consumed once taken): installs from the site (`Permissions.Required`), optional permissions, failed installs (not a cancel), and an "added" notice only for an install the user just agreed to, since updates install too.
    - The bundled install answers its own prompt (`installingBundled`). Installs grant no private browsing and don't share the optional technical data.
    - Permission wording comes from AC's `Addon.localizePermissions` and `localizeDataCollectionPermissions`.
  - **Updates:** AC's `DefaultAddonUpdater` runs a daily WorkManager job per extension, through an `AddonManager` registered with `GlobalAddonDependencyProvider` (`NoFeaturedAddons`, since nothing lists featured add-ons).
    - `scheduleUpdates` follows the store's extensions: added ones are scheduled (idempotent, keeping their time), removed ones unscheduled, and all of them unscheduled with `updateExtensions` off.
    - An update that wants more permissions comes through `WebExtensionSupport`'s `onUpdatePermissionRequest` as an Update prompt, not AC's notification. A newer check replaces an unanswered one.
    - The updater's first check runs right after scheduling. WorkManager's logs (`WM-WorkerWrapper`) show each result. To see the jobs, copy `no_backup/androidx.work.workdb*` off the phone and query `workspec` joined with `worktag` (state 0 is queued, 5 cancelled).
  - **Popups and settings:** the activity's `popupObserver` and `optionsPageObserver` (AC's) show them as an `ExtensionPage`, in the floating page view Glance uses. A popup is an engine session (`PageView.showSession`); a settings page is a custom tab.
    - On the cover it's the bar's `BarPanel.ExtensionPage`: the bar clears a hole for the page and reports where it is (`BarExtensions.onPageArea`) once its surface has grown. Unfolded it's a Glance card.
    - Closing a popup dispatches `UpdatePopupSessionAction` with no session and closes it; a popup that closes itself takes its sheet along.
    - Settings an extension wants in a tab (`openOptionsPageInTab`, as uBlock Origin's dashboard) open as a Quick Tab instead.
    - `PageView` tracks a session it shows directly, so `show(null)` releases it too.
- `glance/`: Glance (board 8), the floating preview of a held link. `GlanceOverlay` takes a title and buttons, so extension pages use it unfolded too.
  - **Opening:** Gecko reports a long press as the tab's `hitResult`; the activity consumes every one, and a link (`HitResult.UNKNOWN`, or `IMAGE_SRC`'s link) opens Glance. It captures the pages on screen first, for the blurred backdrop.
  - **The preview** is an AC custom tab, so `TabManager` (which follows `state.tabs`) and sync never see it. Copy link (`copyGlanceLink`) copies the preview's current URL and leaves Glance open. Open as tab and Split hand it to `TabManager.adopt`, which adds it to the model below its parent (a Quick Tab when the parent is) and turns it into a normal tab.
  - **Drawing:** its page view (`PageView`, which renders custom tabs too) sits under the overlay. `GlanceOverlay` draws the backdrop, the card's header and the buttons on an offscreen layer, and clears a hole with the card's rounded corners for the page.
    - The pages behind hide while it's open (their captures stand in), because two GeckoView surfaces under the hole would overlap in no set order.
    - Taps around the card close it; nothing covers the card's page, so its touches pass through to the preview.
    - On the cover it covers everything, the bottom bar included.
  - It previews at mobile size (`DesktopSites`' `mobileTabs`), and stays open through a fold, without its backdrop.
- `MainActivity.kt`: a `CoordinatorLayout` holding the page views, the bottom bar's anchor, the band under the status bar, and one overlay `ComposeView` for everything drawn over the page.
  - **Cover or inner:** a window at least 600 dp wide at its narrowest counts as the inner screen. A rotated cover doesn't count. In portrait, the unfolded screen uses the cover's layout when `unfoldedPortraitLayout` is `Mobile`.
    - **Default browser:** the activity takes http and https `VIEW` intents and is `singleTask`, so a link from another app reaches the running app (`handleViewIntent`) and opens in a Quick Tab.
    - The activity handles folding itself (`configChanges`), so the page, tab, space and scroll position carry over with no extra work. `onConfigurationChanged` swaps the layout and closes the tab sheet and any edit.
  - **The cover's bars** (`layoutCoverBars`): the bottom bar's anchor, and with `CoverStatusBar.TintedStrip` a strip under the status bar that slides away with it, running left to right through the space's colors. `EngineViewClippingBehavior` gets both heights, and GeckoView's dynamic toolbar their sum.
    - The cover's root has no top padding: the page runs under the status bar, which `updateStatusBar` hides or shows by `coverStatusBar`. The tab sheet and panels leave `statusBarInset` for it, since it shows over them in every mode. A tap along the bottom edge (`bottomEdge`) brings a hidden bar back.
  - **The inner layout** (`layoutInner`): the cover's bars are hidden, and the engine view becomes the page card beside the sidebar or rail.
    - It resets the cover's hide-on-scroll leftovers: container translation, dynamic toolbar height and vertical clipping. Without that, the page sat a bar's height too low in the card.
    - It runs again whenever the root view changes size. Rotating doesn't change the layout mode, and the insets arrive before the new window size, so without this the card kept its old size and the page didn't reflow.
    - Root padding is only the keyboard; the frame and sidebar handle the system bars themselves.
  - **The overlay on the inner screen:** `InnerFrame`, then the sidebar or rail, then the start screen clipped into the card, then the hold menu.
    - The content is wrapped in a full-size `Box`, because the ComposeView's root passes exact window constraints, which stretched the 64 dp rail across the screen.
  - Hide-on-scroll uses AC's `EngineViewScrollingDataBehavior` and `EngineViewClippingBehavior` together with GeckoView's dynamic toolbar height.
    - The behaviors get the page view through `SteadyScrollDeltas`, not directly. AC's own deltas sit in a `StateFlow`, which drops a value equal to the last, so a slow steady scroll lost nearly all of them: the bars barely moved and snapped back on release. With the strip, which moves the page view, that jittered the page.
    - With the strip, the page view moves under the finger, so Gecko scrolls about half as far as the finger while the strip closes, and it answers each pixel the view moves with a pixel of scroll back. `SteadyScrollDeltas` holds back turns smaller than 8 px, or the strip stepped back and forth.
  - **Bottom edge:** with gesture navigation (a navigation bar of 32 dp or less), the cover's page runs under the handle; only the keyboard or a cutout pads the root.
    - The tab sheet keeps its search field above the handle (`gestureHandleInset`), and the edge wave's strip stops above it, so a hold doesn't fight the home gesture.
    - A navigation bar of buttons keeps its own space.
  - Don't switch to `EngineViewScrollingGesturesBehavior`. GeckoView blocks parent touch interception for gestures that start mid-page, so that behavior can hide the bar but never bring it back.
  - The back gesture closes a panel, cancels an edit, or goes back a page.
- `toolbar/`:
  - `PageChrome.kt` holds what the bottom bar and the sidebar share: `PageState`, the URL editor, the loading line and the sidebar's ⋮ menu.
  - `ScrollingBarView` is a `ScrollableToolbar` that AC's behaviors slide with the page: the bottom bar's anchor and the status band.
  - `SteadyScrollDeltas` wraps the page view for those behaviors: deltas from the scroll position (scrollY × zoom), paused during a pinch, with small reversals held back (see `MainActivity`).
  - `AddressInput` decides between URL and search (Google) and formats the domain.
- `sidebar/`: the inner screen (boards 5, 6 and 9c).
  - `Sidebar` (its width set by dragging) and `Rail` (52 dp) reuse the tab sheet's rows (`TabRow`, `FolderRow`, `EssentialsGrid`), so holds, swipes and folders behave the same. The current tab is highlighted in place (`RowHighlight.Current`).
    - The sidebar's rows are 40 dp, through the rows' `height` parameters. The cover sheet keeps 48 dp.
  - **Moving the sidebar's edge:** opening, closing and dragging all draw the sidebar at its full width, revealed by the moving edge. The page is pinned under it (`pinnedPageDp`) and resizes once when the edge stops, because resizing GeckoView every frame would make the page reflow every frame.
    - `sidebarWidthDp` is the width the user set. `sidebarFullDp` is that width fitted to the window. Only the fitted width is ever clamped: on unfold, the layout can run once while the window still has the cover's width, and clamping the stored width then shrank it for good.
    - `SidebarResizeHandle` reaches 10 dp into the sidebar's edge and covers the border beside it.
  - **Border:** 4 dp on every side (`BORDER_DP`), or none with `innerPageBorder` off (square corners then).
    - Every gap in the sidebar is the same 4 dp (`EdgePadding`): the screen edge, between Essentials tiles, and the page side.
    - With the border on, the sidebar has no end padding, because the border is that gap. Adding padding there made the right side 8 dp. On the inner screen the status bar hides with `hideStatusBarUnfolded`. The bottom inset only counts a navigation bar of buttons (taller than 32 dp). Gesture navigation's handle sits over the page; Samsung reports it as a tappable inset, which made the bottom border thicker than the others.
  - A sideways swipe switches spaces wherever a row doesn't take it: rows close on a swipe and consume it first. The space change slides (`AnimatedContent`).
  - The URL field edits the current tab through the activity's `editing`. Over the start screen, typing opens a Quick Tab instead.
  - The media card reads `TabSessionState.mediaSessionState` (the engine fills it in) and drives its `MediaSession.Controller`.
    - Previous and next follow the session's `features`: they skip tracks (`NEXT_TRACK`, `PREVIOUS_TRACK`), seek (`SEEK_FORWARD`, `SEEK_BACKWARD`), or are grayed out.
    - Mute state: AC's Gecko engine never calls `onMediaMuteChanged`, so `MediaSessionState.muted` stays false. The activity keeps its own record (`mutedMedia`), keyed to the session's controller, so a new session starts unmuted.
  - `InnerFrame` paints the space colors with a rounded hole for each page card. GeckoView's surface ignores view clipping, so the cards' rounded corners are this paint. It has no touch handling, so the pages get the cards' touches.
- `ui/`:
  - `Theme.kt` holds the color tokens and the Inter font (bundled in `res/font`; its license is in `assets/licenses`).
    - **Light and dark:** every `EnsoColors` token is a getter that picks its value by `EnsoColors.dark`, snapshot state the activity sets (`applyTheme`). Composables that read a color recompose when it flips, so use the tokens, never `Color.White` or a raw color, for anything that's a surface or text. `EnsoType`'s styles are getters too, for their colors.
    - The dark base is Zen's own (rgb 23, 23, 26): Zen blends a theme's colors into it at the theme's opacity, as Ensō does with the light base, so spaces match Zen's dark mode.
    - Tokens beyond the spec's table: `Card` (cards and menus), `SoftHighlight`, `PillFill` (the bar's buttons), `OnTextPrimary` (icons on a `TextPrimary` fill), `FaviconContrastCircle`, `QuickTabOutline` (deeper gold on light, brighter on dark) and `QuickTabCard`.
    - `EnsoTheme` wraps every Compose view: Material's light scheme as before, or its dark one with Ensō's surfaces, for what Ensō doesn't color itself (the folder name dialog, plain text).
  - `Motion.kt`: `EnsoMotion`, the shared timings and card transitions.
    - Cards fade in and out (`AnimatedVisibility`, or `AnimatedCard` for a value such as the first extension prompt), and the card itself scales through `animateEnterExit` on its `cardModifier`. The sync sheet, the extension prompt and the Extensions card take one.
    - The start screen and pages cross-fade (`PageFadeIn`/`PageFadeOut` in the activity). Its back handler checks `startScreenVisible`, so it's off while it fades out.
  - `Backdrop.kt`: frosted backdrops (`FrostedPage`, `frostedCopy`, `FrostedOver`, `LocalSurfaceBackdrop`). Blurring once on the CPU works before Android 12, which `Modifier.blur` needs.
  - `Favicons.kt`: favicons, the letter fallbacks and the space icons. A favicon cross-fades from its letter once it loads.
    - `Favicon(tab)` (or with a title, URL and tab id) draws a page's icon on its own, with no circle: the user had the neutral circles removed. Only a mostly white icon (`isLight`, such as GitHub's dark-theme mark) gets a dark circle (`FaviconBackdropForLight`). Use it for every tab or page; `LetterFavicon` is the fallback, and the extension icons' own.
    - `FaviconSource` (`Components.favicons`, provided as `LocalFavicons` in the overlay) picks the icon: a loaded tab's page icon, else Zen's icon (`zenIcons`), AC's caches, or the site's `/favicon.ico` (AC's module has no such fallback itself), else null for the letter. It keeps found icons in an LRU, so rows draw them at once.
      - The store's `content.icon` (`pageReports`) only says when a page has reported its icons: AC puts its own made-up icon (a colored square with a letter) there for a page with none. The icon itself comes back through the module, which tells made-up ones apart (`Icon.Source.GENERATOR`).
      - In dark mode the contrast circle flips: a mostly black icon gets a light one. The letters' pastel circles keep dark letters.
  - **Icons module:** `Components.icons` is AC's `BrowserIcons` over the Gecko fetch client. `EnsoApplication` installs it, which adds its built-in extension (`icons@mozac.org`): pages report their icons, and the store's `content.icon` gets them.
  - **Zen's icons:** `ZenMirror.tabIcons()` takes each synced tab's `icon` (mostly `data:` images; Zen's `chrome:` ones are dropped), and `ZenSync.icons` holds them: loaded from the mirror at start, refreshed after each sync, cleared on sign-out. They stay out of `spaces.json`, where they'd be about 16 times its size.
  - `SpaceColors.kt`: a space's chrome colors.
    - `Space.colors()` lays each gradient color over the base at the theme's opacity (`Space.themeOpacity`). A space without colors gets its accent at 16%.
    - `Modifier.spaceSurface` paints one gradient down the whole window, lined up by each surface's window position. The bottom bar, sheet, rows and sidebar therefore read as one, and rows that swipe over it still look seamless.
    - `Space.pageColors()` is the start screen's faint 10% version.
- `Settings.kt`: SharedPreferences values, not yet in any UI, meant to become user settings later.
  - `coverStatusBar` (default `Hidden`) sets the cover's status bar while you browse: `Hidden` (the page reaches the top edge; it shows over the sheet, start screen and panels, or with a swipe down), `OverPage` (always showing, over the page), or `TintedStrip` (over a strip of the space's color that slides away with the bar). The user picked Hidden after seeing the white strip the first build left under the status bar.
  - `hideStatusBarUnfolded` (default on) hides the status bar on the inner screen. Its key still says "top bar", so the saved choice carried over.
  - `quickTabsInTabSheet` (default off) lists Quick Tabs in the cover's tab sheet too, besides the bottom bar's stack.
  - `quickTabLifetimeHours` (default 24, counted since last viewed) sets when Quick Tabs clear.
  - `pageZoomPercent` (default 80) is pages' default zoom on both screens. It applies after a restart.
  - `desktopSitesUnfolded` (default on) asks for desktop sites while the sidebar layout shows.
  - `desktopSitesInSplit` (default off) asks for desktop sites in a split's pages too. Each of those pages is about as narrow as the cover.
  - `startScreenAfterMinutes` (default 30) sets how long the app must be away before it reopens on the start screen.
  - `switchSpacesFromSheetHeader` (default off) lets a sideways swipe on the sheet header switch spaces too. It was the way to switch before the space menu.
  - `spaceMenuHoldMs` (default 300) sets how long a hold takes to open the space menu.
  - `spaceMenuLeftHanded` (default off) moves the space menu's wave and trigger strip to the left edge.
  - `unfoldedPortraitLayout` (default `Mobile`, the cover's bottom bar) chooses the unfolded screen's layout in portrait. `Desktop` keeps the sidebar and page card there too.
  - `innerPageBorder` (default on) draws the thin border around the inner page card. Off, the page sits flush beside the sidebar.
  - `innerSidebarWidthDp` (default 240, the width the user picked) is the sidebar's dragged width.
  - `spaceMenuStripHeight` (default 1, the whole edge) sets how much of the screen's height the edge strip covers, from the bottom up. It never reaches into the bottom bar.
  - `essentialsPerContainer` (default on) shows each space only the Essentials of its Zen container.
  - `syncOpenTabs` (default on) syncs normal open tabs both ways. Quick Tabs never sync.
  - `syncTabNavigations` (default off) lets navigating a tab from Zen move it on the desktop too. It's off because phone pages often redirect, to a login page for example.
  - `zenSyncDryRun` (default off) logs what sync would upload without uploading. It's for testing.
  - `zenSyncCheckSeconds` (default 30) is how often, while the app is open, Ensō asks whether Zen changed anything. 0 leaves only the 5-minute sync.
  - `syncDeviceRecordId` (app state) is this phone's id in the account's Sync device list.
  - `themeMode` (default `System`) picks light or dark, or follows Android's dark theme. `MainActivity.applyTheme` applies it at start and on every configuration change (the activity handles `uiMode` itself): `EnsoColors.dark`, the system bars' icons, the views that took a color once (window, root, page containers), and Gecko's `preferredColorScheme` for pages, which follows the system by itself under `System`.
  - `updateExtensions` (default on) checks extensions for updates daily and installs them.
  - `searchSuggestions` (default on) shows Google's suggestions in bottom search, which sends what's typed to Google.
  - `recentDownloadsHours` (default 24) is how long after a download the actions sheet and the ⋮ menu keep their Downloads button.
  - `readerColorsChosen` (app state) is set once the user picks Reader's colors; until then Reader follows Ensō's theme.
  - `showEnsoOnNewTabs` (default on) shows the ensō fidget on the blank start page.
  - `searchOnStartScreen` (default off) opens bottom search, keyboard up, whenever the cover's start screen shows and each time the app comes back to it (Arc Search's Auto-Open Keyboard).

## Build and run on the Fold

```bash
./gradlew assembleDebug                               # build
./gradlew testDebugUnitTest                           # the JVM unit tests (Zen sync)
./gradlew installDebug                                # install on the connected Fold
adb shell am start -n app.enso.browser/.MainActivity  # launch
adb logcat --pid=$(adb shell pidof -s app.enso.browser)  # app logs
```

The Fold connects over wireless debugging. Wireless debugging must be on in Developer options, with the Fold and the Mac on the same Wi-Fi.

- **First time:** tap "Pair device with pairing code", then run `adb pair <ip>:<pairing-port>` and type the code.
- **Every session:** adb usually reconnects by itself over mDNS. Check with `adb devices`. If the Fold isn't listed, run `adb connect <ip>:<port>`, using the port on the main Wireless debugging screen (not the pairing port). That port changes each time wireless debugging is turned on.
- **Screenshots:** the Fold has two displays, so `screencap` needs a display ID. List them with `adb shell dumpsys SurfaceFlinger --display-id`, then run `adb shell screencap -d <id> -p /sdcard/x.png`.
- **Scripted input:** `adb shell input -d <logical display> tap|swipe|text …`. Logical display 0 is whichever screen is on, and coordinates are in full-resolution pixels: 1248×1972 on the cover, 2448×1848 on the inner screen. The inner screen's SurfaceFlinger ID for screenshots is `4630947004648141459`, and the cover's is `4630947123231501204`. Unfolding needs the user. To place a tap on a popup, read its frame from `adb shell dumpsys window windows`.
  - Long press: `swipe x y x y 900`.
  - Hold a swipe partway: `motionevent DOWN|MOVE|UP x y`. The space menu tests this way: `DOWN 1235 1650` on the right edge, wait, `MOVE` up or down about 189 px (72 dp) per space, then `UP`. The user often uses the Fold while you test, so check the state between gestures rather than assuming your touches were the only ones.
- **The cover's bottom bar:** its row sits at y ≈ 1832 on the cover: the Quick Tabs stack at x 107, "+" at 625 and the chevron at 1140. `adb shell uiautomator dump` lists every view's on-screen bounds (scroll translations included) without touching the screen.
- **Test pages from the Mac:** serve them on `127.0.0.1:<port>` and run `adb reverse tcp:<port> tcp:<port>`. The Fold can then open `http://localhost:<port>/…`.
  - Debug builds take test extras:
    - `--es enso_debug_open <url>` opens a URL in a Quick Tab; add `--ez enso_debug_kept true` for a normal tab, which syncs to Zen.
    - `--es enso_debug_split <tabId>` splits the tab on screen with that tab, and `--es enso_debug_unsplit <splitId>` ends a split. Both sync, so splits can be tested with Zen without unfolding.
    - `--es enso_debug_close <tabId,tabId,…>` closes those tabs, `--es enso_debug_new_folder <tabId>` moves that tab into a new folder ("Ensō test"), and `--es enso_debug_delete_folder <folderId>` deletes a folder, each as the tab sheet does. They take ids (read them from `spaces.json`), so a sync test never has to swipe or tap in the lists that hold the user's own tabs.
    - `--ez enso_debug_desktop_sites true|false` switches desktop sites whatever the screen, until the next fold or unfold.
    - `--ez enso_debug_update_extensions true` checks every extension for an update now.
  - While Ensō is running, add `--activity-single-top` to the `am start` command, or the extras never reach it.

## Testing on the Fold

The user browses with this build on the Fold, so its tabs are real.

- **Back up before testing:** save `adb shell run-as app.enso.browser cat files/spaces.json` (and `shared_prefs/enso_settings.xml`) first.
  - Put backups in `device-backups/<date-time>/` in the project. That folder is git-ignored because it holds personal data.
  - Never put them in the session scratchpad, which is cleared between sessions; a backup was lost that way once.
- **Use your own test tabs:** create them, close only those, and check the user's tabs are intact afterwards.
- **Never write to the user's Zen data without a snapshot.** The spaces collection is their real desktop setup.
  - The app saves a snapshot before its first write. Copy it into the backup folder with `adb shell run-as app.enso.browser cat files/zen-spaces-snapshot.json`.
  - To put the collection back (debug builds only): `adb shell am start -n app.enso.browser/.MainActivity --ez enso_restore_zen_snapshot true`. A restore deletes every record the snapshot doesn't have, so it first keeps the collection as it is (`before-restore-…`), and it refuses a snapshot the account's keys can't read; the log says why.
  - That snapshot is only taken once per account and set of keys, so it can be old. To replace it with the collection as it is now (debug builds only, while Ensō is running, since the account isn't ready at a cold start): `--activity-single-top --ez enso_save_zen_snapshot true`. The log says "Saved a new snapshot of N records" (N counts deletions too). The old one is kept aside as `replaced-…`.
  - The snapshots kept aside are in `files/zen-snapshots/` (list them with `adb shell run-as app.enso.browser ls files/zen-snapshots`). To restore one, add `--es enso_zen_snapshot_name <name>` (the file's name without `.json`) to the restore command.
  - **Zen's own side:** the user's Zen runs on this Mac (profile `~/Library/Application Support/zen/Profiles/04fk82xa.Default (release)`). Read-only, `prefs.js` has `services.sync.lastSync` and `services.sync.spaces.lastSync`, and `weave/logs/error-sync-*.txt` says why a sync failed. When the phone and Zen disagree but the phone matches its mirror, check there first. Never edit that profile.
  - Try risky changes in dry-run first: set `zen_sync_dry_run` to true in the prefs file while the app is stopped. The log (tag `ZenSync`) lists each record it would send and which fields changed.
  - Test with your own tabs and folders in one space, then remove them, so the deletions get tested too.
  - The user may be changing things in Zen at the same time. Zen's tab, folder and split ids start with their creation time in milliseconds, which tells whether a record came from the phone's sync or from the desktop.
- **Restore if needed:** stop the app with `am force-stop`, then run `adb exec-in run-as app.enso.browser sh -c 'cat > files/spaces.json' < backup.json`.
  - Remove the mirror as well, before the app starts: `adb shell run-as app.enso.browser rm files/zen-spaces-mirror.json`. The next sync then downloads everything and uploads nothing. A restored model with a newer mirror is what once made a sync undo Zen's changes; the stamp in `spaces.json` catches that now, and removing the file doesn't rely on it.
- **Edge swipes:** a swipe that starts within about 60 px of the left or right edge is Android's back gesture. Start sideways swipes further in.
- **Dark mode:** the user's Fold goes dark on a schedule (19:00 to 07:00), so check `adb shell dumpsys uimode` (`mComputedNightMode`) for which theme you'll see. To test the other one, set `theme_mode` in Ensō's prefs file while the app is stopped, and put it back after; never change the phone's own setting.
- **Faking time:**
  - Away time: edit `last_stopped_at` in the prefs file while the app is stopped.
  - Quick Tab expiry: edit a test tab's `quick.lastViewedAt` in `spaces.json`.
